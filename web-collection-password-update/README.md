# 작은 서랍 · My Web Collection

수업과 업무 도구를 차곡차곡 모으는 반응형 웹 컬렉션입니다. 제공된 원본 사이트에서 확인한 15개 프로젝트와 2개 학기 폴더를 담았습니다. 소개 문구 일부는 새 디자인에 맞춰 작성했습니다.

## GitHub Pages로 만들기

1. GitHub에서 새 저장소를 만듭니다. 예: `my-web-collection`.
2. 이 폴더 **안의 파일**을 저장소 최상위에 올립니다. `index.html`이 저장소 루트에 있어야 합니다.
3. 가장 간편한 배포: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, **Branch: main / (root)**를 선택하고 Save를 누릅니다.
4. 배포가 끝나면 Pages에 표시되는 주소로 접속합니다. 보통 `https://사용자이름.github.io/my-web-collection/`입니다.

자동 배포를 쓰려면 숨김 폴더 `.github/workflows/pages.yml`도 함께 올리고 Pages의 Source를 **GitHub Actions**로 선택합니다. 두 방식 중 하나만 선택하면 됩니다. 기본 브랜치가 main이 아니면 workflow의 branches를 수정하세요. 별도 설치나 빌드가 필요하지 않습니다.

## 기능

- 전체 목록, 즐겨찾기, 학기 폴더, 분류 필터
- 모든 폴더에서 제목·설명·분류·폴더 이름 검색, 기본/이름/최근/즐겨찾기 정렬
- 카드·목록 보기, 모바일 반응형, 키보드 탐색, `/` 검색 바로가기
- 관리 모드에서 프로젝트 추가·수정·삭제·복사·폴더 이동, 폴더 추가·수정·삭제
- 순서 변경: 데스크톱 드래그 또는 관리 카드의 ↑/↓ 버튼. 모바일은 버튼을 사용하세요.
- JSON 백업·가져오기, 공용 데이터용 `data.js` 내보내기

## 공용 목록 갱신

1. 왼쪽의 **편집자 로그인**을 누르고 비밀번호를 입력한 뒤 편집합니다.
2. 하단의 **data.js 내보내기**를 누릅니다.
3. GitHub의 `data.js`를 내려받은 파일로 교체하고 커밋합니다.
4. 배포가 끝나면 새 방문자에게 변경된 목록이 보입니다. 이미 로컬 편집 데이터가 저장된 브라우저에서는 관리 패널의 **기본 목록 복원**을 눌러 새 공용 목록을 불러옵니다. 복원 전 필요한 로컬 데이터는 JSON으로 백업하세요.

즐겨찾기는 브라우저별로 저장되며 공용 목록에 포함되지 않습니다. 브라우저 저장소를 삭제하거나 다른 기기에서 접속하면 로컬 편집 내용은 이어지지 않습니다. 중요한 편집 후 JSON 백업을 권장합니다. 로컬 데이터가 있으면 공용 data.js보다 우선합니다.

## 원본과의 차이

이 프로젝트는 GitHub Pages에 올리는 독립 프런트엔드입니다. 원본 Google Apps Script의 서버 코드·Google Sheets 데이터베이스와 연결하지 않습니다. 기존 사이트는 변경하지 않았습니다. Google 로그인이 필요한 링크는 원래 접근 권한을 따릅니다. GitHub Pages 자체에는 서버 저장과 사용자 인증이 없으므로 편집자 비밀번호는 브라우저에서 확인하는 화면 잠금입니다. 개발자 도구로 우회할 수 있으므로 실제 접근 제어가 아닙니다. 공용 데이터 보호와 실시간 저장은 인증을 갖춘 서버 API가 필요합니다. 사이트에서 편집해도 GitHub 저장소에 직접 쓰지 않습니다. 여러 기기의 실시간 공동 편집이 필요하면 별도 인증·서버 API를 추가해야 합니다. 비밀키를 프런트엔드에 넣지 마세요.

원본 폴더의 중첩 기능은 이 버전에서는 제공하지 않습니다. 현재 원본에서 확인된 1학기·2학기 구조를 지원합니다. 전체 컬렉션에는 하위 폴더의 프로젝트도 모두 표시됩니다. Google Fonts를 이용하지만 연결이 안 되면 시스템 글꼴로 표시됩니다.

## 로컬 실행

`index.html`을 브라우저로 열면 사용할 수 있습니다. HTTP로 확인하려면 Node.js 환경에서:

```sh
node preview.cjs
```

표시된 `http://127.0.0.1:4173`을 엽니다. 종료는 Ctrl+C입니다.

## 파일

`index.html`: 화면 / `styles.css`: 디자인 / `app.js`: 동작 / `data.js`: 공용 목록 / `favicon.svg`: 아이콘 / `editor-auth.js`: 비밀번호 확인 / `editor-config.js`: 배포용 비밀번호 해시 / `set-password.cjs`: 비밀번호 변경 도구.

문법 확인: `node --check app.js` 및 `node --check data.js`.

## 편집자 로그인 (추가·수정·삭제)

- 시작 시에는 **뷰어 모드**이며 편집 버튼이 표시되지 않습니다.
- **편집자 로그인**에서 비밀번호를 입력하면 프로젝트·폴더의 추가·수정·삭제와 이동·복사·백업 기능이 표시됩니다.
- **편집 종료**를 누르거나 새로고침하면 다시 비밀번호를 입력해야 합니다. 로그인 상태나 평문 비밀번호는 브라우저 저장소에 보관하지 않습니다.
- 임시 비밀번호: `Drawer-2026-Start!`. 배포 전에 아래 방법으로 변경하세요.

### 교사용 화면에서 비밀번호 변경

1. **편집자 로그인** 후 화면 하단의 **비밀번호 변경**을 누릅니다.
2. 현재 비밀번호, 새 비밀번호(12자 이상), 새 비밀번호 확인을 입력합니다.
3. 변경하면 편집이 종료됩니다. **새 비밀번호로 다시 로그인**합니다.
4. 다른 기기에도 적용하려면 관리 패널의 **비밀번호 설정 내보내기**를 눌러 받은 `editor-config.js`를 GitHub 저장소의 같은 파일과 교체합니다.

화면에서 변경한 비밀번호는 현재 브라우저에 해시로 저장되어 새로고침 후에도 유지됩니다. 평문 비밀번호는 저장하거나 내보내지 않습니다. 다른 탭에서 설정이 변경되면 편집이 종료됩니다. 취소하거나 현재 비밀번호 확인 또는 저장에 실패하면 이전 비밀번호가 유지됩니다.

**설정 파일을 GitHub에 반영하기 전에는 다른 기기의 비밀번호가 바뀌지 않습니다.** 브라우저 데이터를 지우면 배포된 설정 파일의 비밀번호로 돌아갑니다. 새 설정 파일을 배포하면 이전 배포에서 만든 브라우저별 비밀번호보다 새 배포 설정을 우선합니다. 이미 열어 둔 탭은 새로고침해야 새 배포 설정을 받습니다. JSON 프로젝트 백업에는 비밀번호 설정이 포함되지 않습니다.

### 파일 도구로 비밀번호 변경

Node.js 환경에서 프로젝트 폴더로 이동한 후 다음을 실행합니다.

```sh
node set-password.cjs
```

화면에 표시되지 않는 입력창에 새 비밀번호(12자 이상)를 두 번 입력합니다. 생성된 `editor-config.js`를 GitHub에 올리면 배포된 사이트의 비밀번호가 바뀝니다. 파일과 브라우저 설정에는 임의 salt와 PBKDF2-SHA256 해시만 저장됩니다. 사이트의 개발자 도구나 localStorage에 평문 비밀번호를 직접 적지 마세요. 제공한 임시 비밀번호는 공개된 기본값입니다.

비밀번호 설정이 누락되거나 HTTPS를 사용하지 않아 검증에 실패하면 편집 버튼은 열리지 않습니다. 로컬 테스트는 `node preview.cjs`를 사용하세요. GitHub Pages의 HTTPS 주소에서도 동작합니다. 기존 편집자가 이미 연 탭은 다시 로드할 때 변경된 비밀번호가 적용됩니다.

비밀번호를 입력해도 저장 방식은 이전과 같습니다. **편집은 이 브라우저에 저장되며 다른 방문자에게 즉시 반영되지 않습니다.** 공용 목록은 data.js를 내보내 GitHub에 반영하세요. 이 화면 잠금은 Google Apps Script 서버 인증 또는 GitHub 계정 권한을 대신하지 않습니다.
